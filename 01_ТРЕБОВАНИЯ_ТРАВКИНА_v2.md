Три источника: (1) методические требования в docx, (2) устные замечания по уже сданным работам, (3) эталонный отчёт, сданный и принятый — `эталон/ЭТАЛОН_ЛР1_Сорокин.pdf`.

## 1. Структура отчёта (обязательные элементы, по порядку)

| № | Раздел | Что внутри |
|---|---|---|
| 1 | **Титульный лист** | Министерство, вуз, «ОТЧЕТ по лабораторной работе №N», название работы кавычками, дисциплина, «Выполнил: Фамилия И.О.», «Группа: ЮР-73», «Проверил: Травкин К.А.», «Москва, 2026», «Работа выполнена: __.__.2026», «Отчёт сдан: __.__.2026», «Зачтено / не зачтено» |
| 2 | **СОДЕРЖАНИЕ** | Поле Word с реальными номерами страниц. Не текст «Обновить поле: Ctrl+A, F9» — это заглушка, за неё возвращают |
| 3 | **ЦЕЛЬ И ЗАДАЧИ ЛАБОРАТОРНОЙ РАБОТЫ** | Абзац «Целью лабораторной работы является…» + нумерованный список задач «1) … 2) …» — каждая задача = одно задание работы |
| 4 | **АППАРАТНОЕ ОБЕСПЕЧЕНИЕ** | Абзац-подводка + таблица «Таблица 1 — Технические характеристики…» + сведения об объектах исследования (образы, их объём, формат) |
| 5 | **ПРОГРАММНОЕ ОБЕСПЕЧЕНИЕ** | Таблица «Наименование \| Версия \| Назначение». Версии указываются у всех программ |
| 6 | **ЗАДАНИЕ 1: <название>** | Теория → ход → рисунки → таблицы → вывод по заданию |
| 7 | **ЗАДАНИЕ 2: …**, **ЗАДАНИЕ 3: …** | То же самое, каждый со своим заголовком |
| 8 | **ВЫВОД** | Что установлено, с числами и конкретикой; не «я научился», а «установлено, что…» |

Разделов «ЗАДАНИЕ 1/2/3» не было в провалившемся отчёте ЛР1 — и это первое, что видно при сравнении с эталоном.

## 2. Оформление

| Параметр | Требование |
|---|---|
| Шрифт | Times New Roman |
| Основной текст | 14 пт |
| Межстрочный интервал | 1,5 |
| Выравнивание | по ширине |
| Подписи к рисункам и таблицам | 12 пт |

| Подписи к таблицам | **над** таблицей, по правому краю |

**Орфография и пунктуация проверяются во всём тексте до сдачи.** После подписей к рисункам ставится точка.

## 3. Рисунки: формат подписей

В эталоне:

```
Рис.1. Подключение образов накопителей и перечень их разделов.
Рис.10. Таблицы разделов образов Ubuntu 64-bit-0.vmdk, Ubuntu 64-bit-1.vmdk, Ubuntu 64-
bit-2.vmdk в байтах.
```

То есть: `Рис.N.` — точка после номера, точка в конце подписи, по центру, 12 пт.

В провалившемся отчёте: `Рисунок 1 — Диски массива, подключённые из образов E01 в режиме чтения` — без точки в конце и в другом формате. Надо приводить к формату эталона (либо единый формат «Рисунок N — … .», но с точкой; в эталоне — «Рис.N.», берём его).

## 4. Как описывать полученные результаты

### 4.1. Без консольных команд

Команды, которые вводились при работе, в отчёт **не переносятся**. Они могут быть видны на скриншоте — этого достаточно. Вместо команды пишется, что было получено:

> «Были получены сведения о подключенных устройствах и их разделах: размерах, типах и опознанных файловых системах.»

Запрещено: «при помощи консольной команды», «командой `mdadm --examine` получено…», «запустил `dd` с bs=1M».

Разрешено: путь через меню программы — «командой меню «Специалист» → «Technical Details Report»», «в окне «Mount Image To Drive» указаны тип и способ монтирования».

### 4.2. Без «результат выглядит следующим образом»

Надписей-анонсов перед рисунком быть не должно. Рисунок вставляется прямо в текст, в том месте, где о нём говорится.

### 4.3. Ссылка до рисунка

Сначала «на рисунке N представлено…», затем рисунок, затем подпись. Обратный порядок — возврат работы.

Допустим диапазон: «Параметры массивов показаны на рисунках 5 – 8.»

### 4.4. Рисунки подробно не описываются

Не «на рисунке в левом верхнем углу видно окно программы с заголовком…». Пишется по существу:

- если есть цветные прямоугольники: «на рисунке одним прямоугольником выделено …, другим — …»;
- если нет: «на рисунке представлено (показано) то-то и то-то».

### 4.5. Язык

| Нельзя | Надо |
|---|---|
| «я открыл», «я запустил», «мне удалось» | безличное: «выполнено открытие», «установлено», «получены сведения» |
| «программа не смогла», «не получилось» | «в доступной версии ПО … не поддерживается», «средствами … установить не удалось, поскольку …» |
| «примерно», «около», «где-то» | точные числа с разрядами: 16 090 398 720 байт |
| «должно быть», «по идее», «вероятно» | утверждение с указанием, откуда оно следует |
| выдуманные числа и «примерные» скриншоты | только то, что реально получено и видно на рисунке |

Научно-технический стиль: термины, полные названия при первом упоминании («уровень RAID5 — чередование с распределёнными блоками чётности»), затем сокращение.

## 5. Порядок описания внутри каждого задания

Эталон держит один и тот же каркас:

1. **Постановка**: что требуется в этом задании.
2. **Теория**: 1–3 абзаца — как устроено (кластер, запись каталога, суперблок, уровень RAID). Без воды, с числами.
3. **Ход**: что и в каком инструменте сделано, без команд.
4. **«Были получены сведения о …»** — конкретика: значения полей, смещения, размеры.
5. **Рисунок** (со ссылкой до него) + подпись с точкой.
6. **Таблица** с названием сверху справа.
7. **Анализ**: расчёт, сопоставление, объяснение расхождений.
8. **Микровывод** по заданию (1–2 абзаца).

## 6. Что считается доказательством

| Требование | Как проверяется |
|---|---|
| Рисунок относится к этой работе и к этому шагу | в отчёте по ЛР1 не может быть скрина из ЛР2. Проверка: совпадение изображений по хэшу |
| Рисунок показывает то, о чём текст | подпись и текст ссылаются на одно и то же окно/значение |
| Числа в тексте совпадают с числами на рисунке | выборочная сверка двух-трёх значений |
| Все задания выполнены | по списку задач из раздела «Цель и задачи» |

## 8. Машинная проверка

Чек-лист выше проверяется скриптом, а не на глаз:

```
python3 ../04_БОТ/tools/check_report_v2.py ОТЧЕТ_ЛР1.docx --compare ../02_ЛР2/
```

Что он ловит: отсутствие разделов и «ЗАДАНИЕ N», заглушки `[Скрин …]` и «Обновить поле», подписи без точки, подписи в чужом формате, подпись без картинки, консольные команды в тексте, запрещённые формулировки, личные обороты, TNR/14/1,5/по ширине, рамки, и главное — **рисунок, совпавший по sha1 с рисунком другой работы** (`--compare`).

Критическая ошибка (чужая картинка, заглушка, нет разделов, нет «ЗАДАНИЕ N», подпись без точки) валит отчёт независимо от набранных баллов.

Проверено на трёх файлах: эталон Сорокина — **97/100 ПРИНЯТ**, `БЫЛО_ОТЧЕТ_ЛР1.pdf` — **46/100 НЕ ГОТОВ** (5 чужих рисунков), `БЫЛО_ОТЧЕТ_ЛР2.pdf` — **67/100 НЕ ГОТОВ** (те же 5). Разбор: `03_РАЗБОР_ПРОВАЛА.md`.
