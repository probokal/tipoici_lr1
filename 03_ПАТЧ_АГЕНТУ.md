# Инъекция для агента в Packet Tracer · ЛР2 · вариант Y=5

Это не анализ и не список вопросов. Это исполнительный документ: агент открывает его, идёт сверху вниз, вставляет блоки, после каждого сверяет контрольную точку. Решения принимаются по правилам из раздела «Дерево решений», а не по догадке.

**Роль агента:** выполнить блоки 0–5 и прогнать контрольные точки К1–К9. Ничего не изобретать: все адреса и VLAN — из эталонной таблицы.

**Роль человека:** вставить команды, вернуть вывод контрольных точек.

## Блок 0. Бэкап (30 секунд, обязательно)

На каждом из B1, B1-S1, B1-S2, B1-S3:

```text
enable
terminal length 0
show running-config
```

Вывод сохранить в текстовый файл. Это точка отката: `configure replace` в Packet Tracer нет, откат — ручной, по этому тексту.

## Блок 1. B1 — маршрутизация и шлюзы

```text
enable
configure terminal

! явно включаем маршрутизацию: не полагаемся на заводскую настройку
ip routing

! физический интерфейс в транк
interface GigabitEthernet0/0
 no shutdown
 exit

! подынтерфейсы — три тегированных
interface GigabitEthernet0/0.10
 encapsulation dot1Q 10
 ip address 16.74.15.1 255.255.255.0
 exit

interface GigabitEthernet0/0.20
 encapsulation dot1Q 20
 ip address 16.74.25.1 255.255.255.0
 exit

interface GigabitEthernet0/0.30
 encapsulation dot1Q 30
 ip address 16.74.35.1 255.255.255.0
 exit

! управляющая VLAN — ОДИН native на всём пути
interface GigabitEthernet0/0.99
 encapsulation dot1Q 99 native
 ip address 16.74.104.1 255.255.255.0
 exit

! DHCP для Sales
ip dhcp excluded-address 16.74.25.1 16.74.25.10
ip dhcp pool SALES
 network 16.74.25.0 255.255.255.0
 default-router 16.74.25.1
 exit

end
write memory
```

Проверка сразу: `show ip interface brief | include GigabitEthernet0/0` — Gi0/0 и все четыре подынтерфейса `up up`.

## Блок 3. B1-S2 — порты, шлюз, STP

```text
enable
configure terminal

vlan 10
vlan 20
vlan 30
vlan 99
vlan 999
exit
vtp mode transparent

interface range FastEthernet0/1 - 4
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 1,10,20,30,99,999
 no shutdown
 exit

! снять старые sticky-записи, иначе новый MAC станет лишним и порт начнёт молча дропать
interface FastEthernet0/6
 switchport mode access
 switchport access vlan 10
 no switchport port-security mac-address sticky
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
 exit

interface FastEthernet0/11
 switchport mode access
 switchport access vlan 20
 no switchport port-security mac-address sticky
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
 exit

interface FastEthernet0/16
 switchport mode access
 switchport access vlan 30
 no switchport port-security mac-address sticky
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
 exit

! управление: единственный адрес на коммутаторе
interface Vlan99
 ip address 16.74.104.22 255.255.255.0
 no shutdown
 exit

! 2960: маршрутизации нет, нужен только шлюз для самого коммутатора
ip default-gateway 16.74.104.1

! корень STP закрепляем явно
spanning-tree vlan 1,10,20,30,99,999 priority 4096

end
write memory
```

**Запрет для агента:** не поднимать `Vlan10`, `Vlan20`, `Vlan30` с адресами. На 2960 это создаёт второго «шлюза», который молча съедает часть трафика. Адрес на коммутаторе должен быть ровно один — `Vlan99`.

## Дерево решений: провалилась точка — что делать

### К5 не идёт (`ping 16.74.104.1` с S2)

1. `show interfaces trunk` на S2 → колонка **Native vlan** у порта в сторону S1. Если не 99 — переустановить (блок 3).
2. Если 99 — порт завис в STP. На S2:

```text
configure terminal
interface FastEthernet0/1
 shutdown
 no shutdown
 exit
end
```

То же на S1 для `FastEthernet0/5`. Это не «перебор версий», а известный дефект Packet Tracer: после массовых правок VLAN он не пересчитывает STP по каждой VLAN, и порт остаётся в forwarding только для одной VLAN.

3. Если и это не помогло — `show interfaces FastEthernet0/1 switchport` на S2 и `FastEthernet0/5` на S1, сравнить `Administrative Mode`, `Native VLAN`, `Trunking VLANs Enabled`. Отличающиеся значения — причина.

### К6 не идёт, а К5 идёт

Односторонняя связь. Значит одна сторона шлёт с тегом, другая ждёт без тега.

* На B1: `show running-config interface GigabitEthernet0/0.99` → должно быть слово `native`.
* На S1: `show interfaces trunk` → Native vlan у `Fa0/5` = 99.
* Затем `clear arp-cache` на B1 и повторить пинг.

### К7 не идёт (ARP пуст)

Кадры от ПК не доходят до роутера. Проверять в этом порядке, без пропусков:

1. На S2: `show interfaces FastEthernet0/6 status` → `connected`, VLAN `10`.
2. На S2: `show port-security interface FastEthernet0/6` → `Port Status: Secure-up`, `Violation Count: 0`. Если `Secure-shutdown` или счётчик растёт — `shutdown`/`no shutdown` на порту и снять sticky (блок 3).
3. Адрес ПК — из сети своей VLAN (блок 5).
4. С ПК: `ping 16.74.15.1` — если шлюз не пингуется, роутер тут вообще ни при чём, проблема в порту или адресе.

### К8 не идёт (DHCP молчит), а пинги идут

1. На B1: `show ip dhcp pool` → `Leased 0` значит запросы не доходят, а не «пул сломан».
2. На S2: порт ПК в VLAN 20 (`show interfaces status`).
3. На B1: `show ip interface GigabitEthernet0/0.20` — `Helper` не нужен, пул локальный.
4. Если ПК в VLAN 10 — DHCP-запрос придёт на `.10`, где пула под 16.74.25.0/24 нет. Это не поломка DHCP, это ПК в чужом порту.

## Что агент сдаёт обратно

1. Вывод К1–К9 (можно построчно, скриншотами — как удобнее).
2. Скриншоты для отчёта: `show ip dhcp binding` на B1, `show interfaces trunk` на S1, `show ip interface brief` на B1, успешные пинги с ПК.

Больше ничего не требуется. Если какая-то точка провалилась — вернуть её номер и вывод команды из дерева решений, а не «не работает».
