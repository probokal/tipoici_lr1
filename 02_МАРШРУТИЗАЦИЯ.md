# ЛР2 · S2 (B1-S2): маршрутизация на коммутаторе — где именно она ломается

Задача этого файла: закрыть вопрос «проблема в S2, и это маршрутизация, а не коммутация» конкретно, без перебора версий.

---

## 1. На коммутаторе маршрутизация живёт ровно в трёх местах

| Место | Что делает | Когда работает |
|---|---|---|
| `ip default-gateway X` | шлюз **для самого коммутатора** (пинги, SSH, SNMP, NTP с него) | только на L2-коммутаторе, когда `ip routing` **выключен** |
| `ip routing` | включает маршрутизацию между VLAN на L3-коммутаторе | 3560/3650; на 2960 такой команды нет |
| `ip route 0.0.0.0 0.0.0.0 X` | маршрут по умолчанию для самого коммутатора | на L3-коммутаторе при включённом `ip routing` |

**Главная ловушка, из-за которой это и выглядит как «коммутация работает, а ничего не пингуется»:**

> На L3-коммутаторе (3560/3650) `ip routing` включён по умолчанию, и в этом состоянии **`ip default-gateway` молча игнорируется**. Строка в конфиге есть, команда принимается без ошибки, но маршрутизатор по умолчанию не появляется. Коммутатор пингует свою подсеть и не пингует всё остальное. Ошибки нет ни одной — просто нет маршрута.

Проверить модель и текущее состояние — три команды на S2:

```text
show version | include Model
show running-config | include ip routing|ip route|ip default-gateway
show ip route
```

## 2. Таблица: что увидел → что это значит → что делать

| Что показала консоль | Диагноз | Действие |
|---|---|---|
| `Model ... 2960` и **нет** строки `ip default-gateway` | шлюза нет вообще | добавить `ip default-gateway 16.74.104.1` |
| `Model ... 3560` (3650), в конфиге есть `ip default-gateway`, `show ip route` — пусто или без `S*` | классическая ловушка: `ip default-gateway` не работает при `ip routing` | добавить `ip route 0.0.0.0 0.0.0.0 16.74.104.1`; строку `ip default-gateway` удалить |
| `show ip route` содержит `S* 0.0.0.0/0` | маршрут есть, дело не в нём | смотреть п.3 ниже |
| на S2 есть адреса на `Vlan10`, `Vlan20`, `Vlan30` | **вот она, «маршрутизация вместо коммутации»**: у ПК шлюз указывает на B1, но ARP за шлюзом может отвечать S2, и трафик уходит в чёрную дыру | на Vlan10/20/30 адресов быть не должно, только `no ip address` + `shutdown` |
| `show ip route` содержит маршрут в ту же сеть через другой интерфейс | конфликт маршрутов | убрать лишний |

## 3. Проверка «на дубли шлюзов» — самая частая причина в этих сборках

На S2:

```text
show ip interface brief | include Vlan
```

Ожидаемое — **одна** строка:

```text
Vlan99     16.74.104.22   YES manual up   up
```

Если там ещё `Vlan10`, `Vlan20`, `Vlan30` с адресами вида `16.74.15.1`, `16.74.25.1`, `16.74.35.1` — значит на коммутаторе поднят второй, «фантомный» шлюз. Компьютер отправляет ARP «кто такой 16.74.15.1», отвечают двое (B1 и S2), кадр уходит то на один MAC, то на другой. Часть трафика умирает внутри S2, часть доходит. Отсюда «то пингуется, то нет» и пустой ARP на роутере.

Лечение:

```text
enable
configure terminal
interface Vlan10
 no ip address
 shutdown
 exit
interface Vlan20
 no ip address
 shutdown
 exit
interface Vlan30
 no ip address
 shutdown
 exit
end
write memory
```

Удалять сами VLAN (глобальные `vlan 10` и т.д.) **нельзя** — они нужны для коммутации портов.

## 4. Полный конфиг S2 — вариант A, коммутатор 2960 (L2)

```text
enable
configure terminal

! ---- база ----
no ip domain-lookup
hostname B1-S2

! ---- VLAN (имена — по методичке, на работу не влияют) ----

vlan 30

vlan 99

vlan 999

exit

interface range FastEthernet0/1 - 4
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 1,10,20,30,99,999
 no shutdown
exit

! ---- абонентские порты ----
interface FastEthernet0/6
 description ACCESS_VLAN10_Admin
 switchport mode access
 switchport access vlan 10
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
exit

interface FastEthernet0/11
 description ACCESS_VLAN20_Sale
 switchport mode access
 switchport access vlan 20
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
exit

interface FastEthernet0/16
 description ACCESS_VLAN30_Servers
 switchport mode access
 switchport access vlan 30
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 no shutdown
exit

! ---- управление: единственный адрес на коммутаторе ----
interface Vlan99
 ip address 16.74.104.22 255.255.255.0
 no shutdown
exit

! ---- маршрутизация для самого коммутатора (L2) ----

```

На 2960 команды `ip routing` нет — и это нормально. Маршрутизацией между VLAN занимается B1.

## 5. Полный конфиг S2 — вариант B, коммутатор 3560/3650 (L3)

Отличия только в блоке маршрутизации:

```text
! ---- маршрутизация для самого коммутатора (L3) ----
ip routing
no ip default-gateway
ip route 0.0.0.0 0.0.0.0 16.74.104.1

! ---- интерфейсы в сторону абонентов оставить коммутируемыми ----
interface Vlan10
 no ip address
 shutdown
interface Vlan20
 no ip address
 shutdown
interface Vlan30
 no ip address
 shutdown
```

Почему `no ip default-gateway` обязателен: пока он есть, легко решить, что «шлюз прописан, значит работает». При включённом `ip routing` эта строка не делает ничего — проверяется только `show ip route` с `S*` в первой строке.

## 6. Проверка со стороны роутера B1 (маршрутизация B1)

Три команды, которые закрывают вопрос «а на роутере всё правильно»:

```text
show running-config | include ip routing
show ip route
show running-config interface GigabitEthernet0/0.99
```

Что должно быть:

| Строка | Ожидание |
|---|---|
| `ip routing` в выводе | **присутствует** (на роутере без неё нет маршрутизации вообще) |
| `show ip route` | `C 16.74.15.0/24` (.10), `C 16.74.25.0/24` (.20), `C 16.74.35.0/24` (.30), `C 16.74.104.0/24` (.99) — четыре connected |
| `.99` в конфиге | `encapsulation dot1Q 99 native` **и** `ip address 16.74.104.1 255.255.255.0` |

Если `show running-config | include ip routing` **пуст** — вот и ответ на всё: на B1 маршрутизация выключена. Субъинтерфейсы при этом честно показывают `up/up`, транки светятся зелёным, а пакеты между VLAN не ходят ни один. Лечится строкой:

```text
configure terminal
ip routing
end
write memory
```

## 8. Разбор фактического вывода (23.10): S2 — 2960, чистый

Что показала консоль и что это значит:

| Строка вывода | Факт |
|---|---|
| `Model number : WS-C2960-24TT` | коммутатор **второго уровня**; маршрутизации между VLAN на нём нет физически |
| `show ip route` → `% Invalid input detected` | на 2960 такой команды нет — это норма, а не поломка |
| `ip default-gateway 16.74.104.1` | единственная «маршрутная» функция 2960 настроена верно |
| `Vlan99 16.74.104.22 YES manual up up` | управляющий SVI поднят, адрес верный |
| `Vlan1 administratively down` | так и должно быть, VLAN 1 не используется |

Вывод: **на S2 искать нечего, он настроен правильно.** Между VLAN маршрутизирует B1.

### Поправка к проверке `ip routing`

`ip routing` на роутере **включён по умолчанию** и в `show running-config` не печатается — он виден только в `show running-config all`. Пустой вывод этой grep-проверки ничего не доказывает. Настоящая проверка — `show ip route`.

### Разделитель «коммутация или маршрутизация»: две команды на B1

```text
show ip arp
show ip route
```

ARP работает **до** маршрутизации. Поэтому:

| `show ip arp` | `show ip route` | Диагноз |
|---|---|---|
| есть записи ПК (16.74.15.x / .25.x / .35.x) | четыре строки `C` | L2 и L3 в порядке → смотреть настройки ПК (шлюз, маска) |
| пусто | четыре строки `C` | кадры не доходят до роутера → **это не маршрутизация** |
| есть записи | нет `C` по какой-то VLAN | подынтерфейс не поднят — вот тут маршрутизация |
| пусто | пусто или только `Serial` | лежит и L2, и L3 |

### Если ARP пуст: выравнивание native VLAN на двух концах провода

Единственное место, где L2 выглядит зелёным, а кадр не доходит.

**S1**, порт в роутер:

```text
enable
configure terminal
interface FastEthernet0/5
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 1,10,20,30,99,999
 end
```

(на 2960 команды `switchport trunk encapsulation dot1q` нет — если консоль ругнётся, строку пропустить)

**B1**:

```text
enable
configure terminal
interface GigabitEthernet0/0.99
 encapsulation dot1Q 99 native
 ip address 16.74.104.1 255.255.255.0
 no shutdown
 exit
end
clear arp-cache
```

Затем **на обоих концах** `show interfaces trunk` — колонка **Native vlan** должна быть `99`. Если на S1 там `1`, а на B1 `99` — кадр без тега уходит в VLAN 1 и до подынтерфейса .99 не доходит никогда.

### Проверка соответствия «порт → VLAN → адрес ПК»

| Порт S2 | VLAN | Адрес ПК из | Шлюз |
|---|---|---|---|
| Fa0/6 | 10 | 16.74.15.0/24 | 16.74.15.1 |
| Fa0/11 | 20 | 16.74.25.0/24 | 16.74.25.1 |
| Fa0/16 | 30 | 16.74.35.0/24 | 16.74.35.1 |

Если адрес не из сети своей VLAN — не пингуется ничего, независимо от коммутации и маршрутизации.
