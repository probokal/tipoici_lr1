## 2. Э2 — RAID в Kali (детально)

### 2.1 Подключить 4 вещдока к Kali VM (5 минут)

1. Выключить Kali. Проверить, что **старая Ubuntu-ВМ тоже выключена** (чтобы не было двух писателей в одни vmdk).
2. VM → Settings → Add… → Hard Disk → Next → тип SCSI (Recommended) → Next → **Use an existing virtual disk** → Browse → файл из `…\лр 1\Lab1` (vmdk; если не видно — выбери «All files»). Повторить для всех 4 vmdk.
3. Для каждого добавленного диска: Advanced… → включить **Independent** → **Non-persistent** → OK. (Защита: любые случайные записи исчезнут при выключении VM.)
4. Включить Kali.

Запреты на весь Э2: массивы не пересоздавать; монтировать только `-o ro`; `mkfs`/`fsck`/`mdadm --create` не запускать.

### 2.2 Первый запуск: проверить, не собрал ли mdadm массивы сам

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT
cat /proc/mdstat
```

Ожидаемо: `sdb…sde` по 40 ГБ, у каждого 5 разделов (1 МБ + 4 крупных).
Если в `/proc/mdstat` уже есть массивы (автосборка) — сразу перевести в режим без записи:

```bash
for m in /dev/md*; do sudo mdadm --readonly "$m" 2>/dev/null; sudo blockdev --setro "$m"; done
grep -H . /sys/block/md*/md/sync_action 2>/dev/null   # если resync/recovery — остановить:
for m in /dev/md*; do echo idle | sudo tee /sys/block/${m##*/}/md/sync_action >/dev/null; done
mount | grep md || echo "ничего из md не смонтировано"
```

### 2.3 Карта массивов — главный факт этого этапа

```bash
mkdir -p ~/evidence && cd ~/evidence
for dev in /dev/sd[b-z][0-9]*; do
  if sudo mdadm --examine "$dev" >/dev/null 2>&1; then
    echo "=== $dev ==="
    sudo mdadm --examine "$dev" | grep -E "Array UUID|Name|Raid Level|Raid Devices|Device Role|Array Size|State"
  fi
done | tee raid_map.txt
```

Что смотреть: `Array UUID` (одинаковый = один массив), `Raid Level`, `Device Role` (порядок дисков — нужен для R-Studio/UFS), `Array Size`.
**Пришли `raid_map.txt` — по нему я подтвержу сборку и ты продолжишь.**

Скрин: терминал с `lsblk` и началом `raid_map.txt` (скрин № в журнале).

### 2.4 Сборка массивов только для чтения

По карте из 2.3 (пример синтаксиса — подставь свои устройства):

```bash
sudo mdadm --assemble --readonly /dev/md0 /dev/sdb2 /dev/sdc1 /dev/sdd1 /dev/sde1
cat /proc/mdstat
sudo mdadm --detail /dev/md0 | tee -a mdadm_detail.txt
```

- Если mdadm отказывает из-за чужого homehost — добавь в конец `--force` (допустимо **только** для `--readonly`-сборки; записи не будет).
- Если `/dev/md0` занят — используй свободный номер.
- Повторить для остальных массивов; ожидаемо — 4 массива (RAID0 /, RAID5 /home, RAID1 /var, RAID10 /opt по ТЗ; фактический состав — из карты).

Скрины: `/proc/mdstat` + `--detail` по каждому массиву.

## 3. Э4 — Задание 2: метаданные удалённых файлов (детально)

### 3.1 Найти массив с /home и смонтировать только для чтения

```bash
sudo mkdir -p /mnt/lr1
for m in /dev/md*; do echo "== $m"; sudo mount -o ro,noatime "$m" /mnt/lr1 2>/dev/null && { ls /mnt/lr1 | head; sudo umount /mnt/lr1; }; done
# нашли массив, где в корне home/ (или сразу kriko/) — монтируем его:
sudo mount -o ro,noatime /dev/mdX /mnt/lr1
ls -la /mnt/lr1/home/kriko/deleted | head -30
```

### 3.2 Удалённые записи средствами Sleuth Kit

```bash
sudo fls -r -d -p /dev/mdX | tee ~/evidence/fls_deleted.txt
```

- Если в выводе есть имена файлов — отлично, берём их.
- Если только иноды/пусто — маршрут Б:

```bash
sudo debugfs -R "lsdel" /dev/mdX | tee ~/evidence/lsdel.txt
```

Имя файла, если оно не сохранилось, восстанавливается по содержимому (первые байты):

```bash
sudo dd if=/dev/mdX bs=4096 skip=<номер_первого_блока> count=1 2>/dev/null | strings | head
```

и в отчёте помечается: «имя восстановлено по содержимому».

### 3.3 Метаданные по каждому файлу (это и есть таблица задания 2)

```bash
sudo fsstat /dev/mdX | grep -i "block size"        # размер блока (обычно 4096)
sudo istat /dev/mdX <inode> | tee -a ~/evidence/istat_all.txt
```

Как заполнять таблицу:

| Колонка | Откуда |
|---|---|
| имя | `fls` (или восстановлено по содержимому) |
| № начального кластера | первый Direct Block в `istat` |
| количество кластеров | число блоков, занятых файлом (из `istat`) |
| расчётный размер | кластеры × размер блока (из `fsstat`) |
| реальный размер | поле size в `istat` |

Пояснение для отчёта (коротко, без воды): почему у ext4 после удаления имя и указатели стираются, а содержимое остаётся; что показывает `istat`; почему расчётный размер может не совпадать с реальным.

Скрины: листинг `deleted`, `fls -d`, 2–3 `istat`, `fsstat` с размером блока.

## Блок R3. Чистая пересборка набора RAID5 в R-Studio (если структура не открывается)

Симптом: R-Studio распознаёт массивы (virt-mdadm-…), но в Root набора RAID5 только $InodeIdx, папок нет. На RAID0 структура при этом видна.
Причина: смешанная конфигурация — 16 регионов (по 4 на диск) дают 4 набора, R-Studio путает части.

Лечение — повторить процедуру примера один-в-один:
1. Удалить ВСЕ виртуальные наборы и ВСЕ регионы (правый клик → «Удалить»), «Обновить» (Ctrl+R).
2. Создать РОВНО 4 региона — только члены RAID5:
   - диск с 5 разделами (DISK1): начало 21 476 933 632, размер 5 368 709 120;
   - диски 2–4: начало 21 475 885 056, размер 5 368 709 120.
3. Через несколько секунд появится один набор virt-mdadm-ubuntu-server:1 (Ext4) → Root → kriko + lost+found → Рис. 19.
4. Если структура не появилась — не тратить время: том /home снимать в UFS Explorer (он читает E01 напрямую и собирает mdadm сам). В отчёте: R-Studio — распознавание/сборка наборов и корневой том, UFS — том /home.

## Блок R4. Дерево диагностики: «набор есть, структуры нет»

Если R-Studio показывает распознанные наборы, но в Root только $InodeIdx:

1. **Смотреть на роли членов** в `cat /proc/mdstat` (квадратные скобки). Нестандартные роли (например, RAID5 `[0][1][2][4]` вместо `[0][1][2][3]`) — типичная причина: ручной конструктор R-Studio не применяет роль из суперблока mdadm и сдвигает полосы.
2. **Дискриминатор** — открыть RAID1 (`/var`). Дерево есть → причина в метаданных конкретного массива; дерева нет → R-Studio 8.8 не читает не-RAID0.
3. **Обход, который работает всегда**: собрать массив в Kali (mdadm), выгрузить том в плоский образ (`dd if=/dev/md125 of=…/home_md1.img bs=4M conv=sparse`), открыть образ в R-Studio — парсер mdadm в этом пути не участвует.
4. **UFS Explorer** разбирает mdadm по ролям — им и снимаем том, если R-Studio пасует.

Полная версия: `05_ДИАГНОСТИКА_RAID5.md`. Правила против повторения одного и того же: `06_АНТИЦИКЛ.md`.
