# §1. Поднять массивы в Kali

Массивы живут в памяти. После падения виртуалки их нет, `/proc/mdstat` пуст. Это не поломка.

Вставить целиком:

```bash
set -o pipefail
mkdir -p ~/evidence /mnt/ewf
echo "== МЕСТО =="; df -h / | tail -1
echo "== ОБРАЗЫ =="
cd /mnt/hgfs/e01 || { echo "НЕТ /mnt/hgfs/e01. Что есть:"; ls -1 /mnt/hgfs; return 1 2>/dev/null || exit 1; }
ls -lh *.E01 2>/dev/null || { echo "Нет файлов .E01"; ls -1 | head; return 1 2>/dev/null || exit 1; }
i=0
for f in *.E01; do
  [ -e "$f" ] || continue
  i=$((i+1))
  sudo mkdir -p /mnt/ewf/d$i
  sudo ewfmount "$f" /mnt/ewf/d$i || { echo "ewfmount не смог: $f"; return 1 2>/dev/null || exit 1; }
  echo "  $f → /mnt/ewf/d$i/ewf1"
done
echo "== ОБРАЗОВ ПОДКЛЮЧЕНО: $i =="
: > ~/evidence/loops.txt
for n in $(seq 1 $i); do
  L=$(sudo losetup -Pf --show /mnt/ewf/d$n/ewf1) || { echo "losetup не смог на диске $n"; return 1 2>/dev/null || exit 1; }
  echo "диск $n → $L"; echo "$n $L" >> ~/evidence/loops.txt
done
echo "== СБОРКА =="
sudo mdadm --assemble --scan --readonly 2>&1 | tee ~/evidence/00_assemble.txt
sudo mdadm --assemble --scan --force --run --readonly 2>&1 | tee -a ~/evidence/00_assemble.txt
cat /proc/mdstat | tee ~/evidence/01_mdstat.txt
MD=$(awk '/raid5/ && /active/ {print $1; exit}' /proc/mdstat)
if [ -z "$MD" ]; then
  echo "RAID5 не найден. Роли по разделам:"
  for n in $(seq 1 $i); do sudo mdadm --examine /dev/loop$(($n-1))p* 2>/dev/null; done | grep -E "Device Role|Raid Level|Array UUID|State" | head -40
else
  echo "ГОТОВО. массив /home = /dev/$MD"
  sudo mdadm --detail /dev/$MD | head -12
fi
```

**Должно появиться:**

```
ГОТОВО. массив /home = /dev/md125
/dev/md125:
           Raid Level : raid5
          Array Size : ...
                State : clean
```

Номер `md125` может быть другим — это нормально, дальше номер подставляется сам.

**Если написало `RAID5 не найден`** — скопируй вывод про роли (`Device Role`, `Raid Level`) и пришли. По нему видно, какие разделы в какой массив, гадать не нужно.

> Здоровая привычка: этот блок выполняется после каждой перезагрузки Kali. Он один, запоминать ничего не надо.

# §2. Цифры для таблицы 3 — RAID

Вставить целиком, работает после §1:

```bash
MD=$(awk '/raid5/ && /active/ {print $1; exit}' /proc/mdstat)
: > ~/evidence/02_raid.txt
for n in $(seq 1 $(wc -l < ~/evidence/loops.txt)); do
  echo "===== DISK$n =====" >> ~/evidence/02_raid.txt
  sudo mmls /mnt/ewf/d$n/ewf1 >> ~/evidence/02_raid.txt 2>&1
done
for md in $(grep -o '^md[0-9]*' /proc/mdstat); do
  echo "========= /dev/$md =========" >> ~/evidence/02_raid.txt
  sudo mdadm --detail /dev/$md >> ~/evidence/02_raid.txt 2>&1
done
cat ~/evidence/02_raid.txt | head -60
```

**Что взять в таблицу 3:**

| Колонка | Откуда брать |
|---|---|
| Имя файла | `DISK1.E01` … `DISK4.E01` |
| Начало тома, байт | `mmls`, колонка `Start` сектора × 512 |
| Размер тома, байт | `mmls`, число секторов (`End` − `Start` + 1) × 512 |
| Уровень RAID | `mdadm --detail`, строка `Raid Level` |
| Размер конечного тома | `mdadm --detail`, строка `Array Size` |
| Точка монтирования | из §3 |

**Самопроверка (сильный аргумент на защите):** четыре диска по 40 ГБ дают RAID0 — 160 ГБ, RAID5 — 120 ГБ, RAID10 — 80 ГБ, RAID1 — 40 ГБ. Совпало с `Array Size` — уровень определён верно.

Если арифметика не сходится — не подгоняй, пришли `02_raid.txt`.

# §3. Скрин дерева тома `/home`

```bash
MD=$(awk '/raid5/ && /active/ {print $1; exit}' /proc/mdstat)
sudo mkdir -p /mnt/lr1
sudo mount -o ro,noload /dev/$MD /mnt/lr1
ls -la /mnt/lr1
ls -la /mnt/lr1/kriko
mount | grep lr1 | tee ~/evidence/06_mount.txt
```

`-o ro` — только чтение. `noload` — журнал не проигрывается, том не меняется. Это важно: исследование не должно менять вещдок.

**Снять два кадра:**

1. Окно терминала с `ls -la /mnt/lr1/kriko`, где видны каталоги `deleted` и `docs`. Подпись потом: «Содержимое каталога пользователя на восстановленном томе.»
2. Строка `mount`, где видно устройство и точку `/mnt/lr1`. Подпись: «Монтирование восстановленного тома в режиме чтения.»

Главное на первом кадре — **оба каталога в одном окне**. Иначе придётся снимать дважды.

# §4. Удалённые файлы → таблица 4

```bash
MD=$(awk '/raid5/ && /active/ {print $1; exit}' /proc/mdstat)
sudo fls -r -d /dev/$MD > ~/evidence/04_deleted.txt 2>&1
cat ~/evidence/04_deleted.txt
```

Строки выглядят так:

```
d/d * 1234:	old_report.doc
r/r * 1250:	photo.jpg
```

Число до двоеточия — номер inode. Плюс `r/r * 1250` иногда с `(deleted-realloc)` — это перезаписанная запись, для отчёта она тоже годится, но помечается отдельно.

Взять нужные файлы (те, что в каталоге `deleted`, — обычно 2–3) и по каждому:

```bash
sudo istat /dev/$MD 1234 | tee -a ~/evidence/05_inode.txt
```

**Что взять в таблицу 4:**

| Колонка | Откуда |
|---|---|
| Имя файла | из `fls` |
| № начального кластера | `istat`, строка `Direct Blocks`, первый адрес |
| Количество кластеров | `istat`, `Size` ÷ 4096, округлить вверх |
| Расчётный размер, байт | кластеры × 4096 |
| Реальный размер, байт | `istat`, строка `Size` |

**Правило проверки:** расчётный размер совпадает с реальным или расходится в пределах одного кластера. Расхождение больше — данные перезаписаны, и это пишется в отчёт честно, а не подгоняется.

# §5. Копия `/home` и рис. 22

Сначала посмотреть свободное место:

```bash
df -h /
```

Нужно 8 ГБ. Если меньше — сразу §5.2, вариант с gzip.

## 5.1 Копия на локальный диск

```bash
MD=$(awk '/raid5/ && /active/ {print $1; exit}' /proc/mdstat)
sudo dd if=/dev/$MD of=$HOME/evidence/home_md1.img bs=1M conv=sparse status=progress
sync
ls -lh ~/evidence/home_md1.img
du -h ~/evidence/home_md1.img
file -s ~/evidence/home_md1.img
```

**Почему на локальный диск, а не в общую папку.** Общая папка VMware — не диск, а сетевой драйвер. Тридцать гигабайт через него при 2 ГБ памяти роняют виртуалку. Именно это и случилось в прошлый раз.

Ожидается:

```
-rw-r--r-- 1 mironov mironov 30G ... home_md1.img      ← логический размер
1,2G	home_md1.img                                   ← занято на диске
/home/mironov/evidence/home_md1.img: Linux rev 1.0 ext4 filesystem data
```

Третья строка — главная. Если `file -s` не сказал `ext4`, копия негодная, повторить.

**Снять кадр для рис. 22:** окно с `ls -lh` и `file -s`, обе строки в кадре.

## 5.2 Если места мало

```bash
sudo dd if=/dev/$MD bs=1M conv=sparse | gzip -1 > ~/evidence/home_md1.img.gz
```

Проверка тогда: `zcat ~/evidence/home_md1.img.gz | file -s -` — должно сказать `ext4`.

## 5.3 Если образ нужен в Windows (для дерева из R-Studio)

Через общую папку не копировать. По SSH:

```bash
sudo systemctl start ssh
ip -4 a | grep inet
```

В PowerShell на хосте:

```powershell
scp mironov@192.168.108.129:/home/mironov/evidence/home_md1.img "D:\загрузки\лр 1\"
```

Дальше в R-Studio: «Открыть образ» → `home_md1.img` → Root → `kriko` → `docs` / `deleted`. Это и есть обход дефекта R-Studio 8.8 при нестандартных ролях массива — в отчёт идёт честной фразой, см. §7.6.

Размонтировать после работы:

```bash
sudo umount /mnt/lr1
sudo mdadm --stop /dev/md*
sudo losetup -D
```

# §6. Скрин FTK «Mount Image To Drive»

Windows, 3 минуты.

1. FTK Imager → `File → Add Evidence Item…` → `Image File` → выбрать `DISK1.E01`.
2. В дереве слева: `Evidence Tree` → правый клик по образу → `Mount Image To Drive`.
3. В окне выбрать **`Read Only`** (`Block Device / Read Only`) и букву диска.
4. Снять окно целиком: путь к образу, галочка `Read Only`, буква.

Подпись: «Монтирование образа носителя в режиме чтения.»

Критерий приёмки: `Read Only` видно глазом. Без этого кадр не годится — в отчёте он доказывает, что исследование шло без изменения вещдока.

Девять шагов, каждый заканчивается проверяемым результатом. Если на каком-то шаге появилось не то, что написано в «должно появиться» — стоп и вывод в чат. Дальше идти нельзя: ошибка в §1 делает бессмысленными §2–§5, а ошибка в §4 — таблицу 4.
